# Existing Project Workflow

1. Inspect repository, build, tests, dependencies, architecture, and conventions before proposing changes.
2. Map the requested change to existing modules and owners.
3. Identify regressions, migrations, compatibility constraints, and security impact.
4. Prefer the smallest viable change; do not redesign unrelated components.
5. Define a task contract and acceptance criteria.
6. Implement with focused tests.
7. Review specification compliance and engineering quality separately.
8. Verify the actual build/test result.
9. Report changed files, evidence, risks, and remaining work.
